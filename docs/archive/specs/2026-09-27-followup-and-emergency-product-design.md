# 追问与产物的重新定界

日期：2026-09-27
状态：待执行
关联：`core/slot_schemas.py`、`core/dialogue_policy.py`、`core/dialogue_understanding.py`、`core/assistant_graph.py`、`core/uncertainty.py`

## 0. 统一实施原则（四条决策共用）

> **代码负责"必须包含什么"，模型负责"怎么说"，代码再核对"有没有包含"。**

这条原则同时解决了两类相反的病：固定模板（死板、不可维护）和放任模型（可能漏掉必须说的东西）。
应用方式：代码把"必须覆盖的要点"作为**契约**传给模型 → 模型自由措辞 → 代码**核对输出是否覆盖** →
覆盖不到才兜底。**兜底从"默认路径"降级成"异常路径"。**

## 1. 四条决策

### 决策 1：危险场景直接给安全处理方法，不追问、不确认

`danger_veto` 为真时：

- **不追问槽位**（已实现：`no_questions` 把 `ask_critical_question` 降级）
- **也不问"人撤离了吗"这类安全确认问题**（**新增**：之前的设计里我提过要加安全确认，
  这条被否掉。危险场景一律无问句，直接给处理方法）
- 落地：`no_questions` 为真时 `question` 必须为 `""`，且回复不得以问号结尾（有测试）

### 决策 2：删掉固定问句兜底，改由模型按 `missing` 生成

- **把代码算出的 `missing` 喂进规划器提示词**（现在没有喂，模型只能猜该问什么）
- **提示词契约**：`missing` 非空时，`question` 必须指向其中一个槽位；确实无需追问可留空
- **删除 `Slot.question` 兜底路径**（`core/dialogue_policy.py::_question_for_missing` 里读固定串那段）
- 理由（结构性）：现在 32 个小类靠 9 套模板硬撑，**12 个小类只有一句"能再具体描述一下吗"**。
  这条路不可维护，不是"补得不够多"。实测模型 12/12 自己写问句、兜底触发 0 次。
- **先测再删**：见 §2。
- **`Slot` 数据类里的 `question` 字段**：删除兜底后无用途，但它也是"人类可读的槽位说明"，
  先保留字段、只切断调用路径，避免一次性大改。

### 决策 3a：槽位按「决策价值」分三类（替代 `critical` 布尔）

**为什么不能用"会不会改变动作"当唯一判据**：`长期还是临时` 这类信息不影响"下一步做什么"，
但**会影响法规适用与处罚档次**。只看动作就把它判成"不该问"，会造成报告误判 —— 用户指出的是对的。
但"那就都问"也不成立（会退回填表）。正确做法是**按缺了它的后果分三类**：

| 类 | 判据 | 处理 | 例 |
| --- | --- | --- | --- |
| **A 决策级** | 缺了它，**下一步动作会错** | **追问**（一轮一个） | 有没有人在里面；是设施故障还是通道占用 |
| **B 报告级** | 缺了它，**法规适用 / 责任归属 / 处罚档次会不同** | **不追问**，但在报告里写成**条件分支** | 占道是长期还是临时；结构是老化还是擅改 |
| **C 装饰级** | 缺了它不影响任何结论 | 不问、不提 | 具体颜色、无关细节 |

**B 类的写法要求（这条是防误判的关键）**：

- 报告必须写成**条件分支**而不是省略。例：
  「持续时长未知：若为长期占用，适用《城市道路管理条例》第 X 条（可处罚）；若为临时占用，适用第 Y 条（责令改正）。」
- **不能只写"信息不足"这种空话** —— 那是把不确定性丢回给用户，等于没做判断。
- 只有**法规适用确实不同**的槽位才写分支，其余归 C 类，避免报告又长又绕。

### 决策 3b：`missing` 必须喂给报告（根因，和决策 2 是同一个）

现在 `missing` 是"代码算出来但没人用"的信号：**既没喂规划器**（所以问句靠猜）、
**也没喂报告**（所以「仍需确认」章节靠猜、写得含糊）。两边都在猜同一个字段。

- 喂规划器 → 解决"问什么"（决策 2）
- 喂报告 → 解决"B 类缺失怎么写成条件分支"（决策 3a）

**验收**：报告的「仍需确认」章节里的每一项，必须能对应到一个 B 类槽位；
出现无法对应的泛泛表述即为不合格（可写成测试）。

### 决策 3：追问只挂在「口头判断」路径上，并优化口头判断内容

- `route` 按**产物**分：口头判断 / 报告 / 应急指引。**追问是「口头判断」的可选尾巴，不是报告的尾巴。**
  报告末尾接问句读起来像"表单填完了再问你一句"，比纯追问更生硬。
- **纯追问不该存在**：有可判结论就先给结论再附一个问句。
- **优化口头判断的内容**（新增，且可能是"生硬"的主因）：
  现在的分裂是 —— `answer_reply` 给口语化的"答+问"，而 `report_preliminary` 给模板化的
  `### 一、初步判断 / ### 二、仍需确认`。**同一段对话里出现两种文体。**
  要做的：口头判断的提示词要带上**已知事实 + 缺什么 + 是否危险**，产出一句具体的判断，
  不是泛泛的"属于较高风险隐患"。

### 决策 4：`danger_veto` 时产物是「应急指引」，不是报告

现状（待复测确认）：危险 + 有隐患信息 → `no_questions` 把动作降级成 `report_preliminary`
→ **用户在逃生，系统给他一份带「### 一、初步判断 / ### 二、仍需确认」的报告**。产物类型是错的。

- `danger_veto` → **不进 `search`/`report`**、**不邀请建单**、**不追问**
- **措辞由模型组织，不是固定模板**（按 §0 原则）：
  - 代码传入"必须覆盖的安全要点"（如火灾：撤离、119、不要返回取物）
  - 模型组织语言
  - 代码核对输出是否覆盖要点（关键词级），覆盖不到才前置兜底句
- **指引类型要补**：现在 `guidance_line` 只有火灾 + 燃气。**地震、触电、坍塌没有** —— 要补
- 保留的硬要求：回应急指引**不得**出现问句

## 3. 验收标准

1. `danger_veto=True` 时：回复**不含任何问号**、不出现 `interrupt`、不进 `report` 节点（有测试锁）
2. 删兜底后，`missing` 非空而模型未给问句的情况**有日志可查**（不能静默什么都不问）
3. `Slot.question` 不再被任何生产路径读取（grep 可验证）
4. 规划器提示词里能看到 `missing` 被传入（测试断言提示词内容）
5. 口头判断与报告两种产物的**文体差异**有明确边界：追问只出现在口头判断路径
6. 应急指引要点覆盖：火灾/燃气/地震/触电/坍塌各有一条用例，且都不是固定串（模型产出）
7. 全量 pytest 通过（既有失败 `tests/test_vector_delete_api.py` 除外）

- 不改前端（若产物类型变化需要前端区分，另出契约）
