## 0. 三条能讲 / 三条不能讲

**能讲（都有原始记录）**
1. **换模型不行**（口径 A：同 harness、同一天、同 74 题 × 3 次采样、同一份 planner prompt）
   云端 MiMo 小类 **92.7%**，本地 Qwen2.5-3B 裸跑 **58.3%** → **−34.4 pt**，远超题目级 95% CI **±6.4 pt（n=64）**，统计显著。
   （交叉印证：主工程自己的协议同一天测得 MiMo 0.917，两者差 1pt，落在噪声内。）
2. **架构值多少**：同一个 MiMo，走完整链路（prompt + `scope_guard` + 图）**92.7%** vs 裸 HTTP 一句话契约 **74.0%**
   → **18.8 pt 全部来自那套脚手架**。这是「为什么要把格式与范围从模型里剥出去」最直接的量化。
3. **微调买到什么**（口径 B，**消融口径**）：短契约下 3B 从 **50.5% → 84.9%（+34.4 pt）**，
   正样本 JSON 合规率 **100%**（同契约下 MiMo 只有 **83.3%**）。训练成本实测：**844 秒 / 192 步 / 峰值显存 5.04 GB**。

**不能讲（会被追问打）
- ❌ 「小模型能上生产」——适配器按**短契约**训练，主链路的契约不同，**口径 A 下的小模型（含微调版）没有测量结果**。
- ❌ 「微调后追平/超过商业模型」——那是**跨口径相减**（拿 A 的 MiMo 减 B 的 LoRA），无效；
  同口径下 MiMo 的失分主要来自 **16.7% 的回答压根不是 JSON**，不是分类能力不如。
- ❌ 「口语泛化问题解决了」——题集固定 64 条，且训练集自带约 10 种口吻模板，**可能是贴合这批口吻**。

## 1. 四个面试问答

**Q1：有没有考虑过用本地小模型省 API 费用？**
> 考虑过，而且做了对照实验。同一批 74 题、同一天、同一个 harness、每例 3 次采样：云端 MiMo 小类 92.7%，
> 本地 Qwen2.5-3B 裸跑 58.3%，**差 34.4 个点，远超题目级置信区间（±6.4 pt）**。所以我们不换 —— 这不是"感觉不行"，
> 是统计显著的结论。顺带还有个反直觉的发现：小类的低分主要不在大类判断（大类 74.0%），而在细分类和输出契约。

**Q2：那你们这套 LangGraph + 护栏，价值到底在哪？**
> 有一个我自己测出来的数：**同一个模型**，走我们完整链路 92.7%，裸调用一句话提示词 74.0% —— 18.8 个点全在
> 「提示词 + 输出契约 + 范围护栏」这套工程脚手架里。这就是我们为什么要让**模型只负责语义**，
> 把格式、范围、检索、报告结构都放在代码侧：这部分价值跟模型规模是一个量级。

**Q3：你做过微调吗？有用吗？**
> 做过，但要先声明它是**消融口径**（不走主链路，只测模型能力）。在「只准按私有编码词表输出」的极简契约下，
> 256 条领域样本 + 一次 QLoRA（单卡 8GB，14 分钟），把 3B 从 50.5% 拉到 84.9%（+34.4 pt），
> 而且 **JSON 合规率 100%**。同契约下 MiMo 是 74.0%、合规率只有 83.3%。
> 但这个结果**不能投产**：适配器学的是短契约，主链路要的是 `issues/slots/question/premises_scope` 那套。

**Q4：那为什么不接着在主链路上微调（v3）？**
> 两个硬约束。① 显存：主工程的 planner prompt 实测 **1748 token**（短契约只有 436），主契约单条样本约 **2081 token**，
> 序列长度是 v2 的 2.5~3 倍；v2 在 836 token 时峰值已 5.04 GB，8GB 单卡基本必崩。
> ② 标签：我们没有主契约格式的训练标签，得先用教师模型（MiMo）生成并做校验，那是"蒸馏"而不是"微调"。
> 要做的话路径很清楚：云卡（24GB）+ 教师标签 + 在口径 A 上复测 —— 我把它列为下一步工作，而不是硬在本机上扛。

### 2.2 口径 B：短契约（一句话 + 编码词表，**消融口径，产物不投产**）

| 指标 | 云端 MiMo | 3B 裸跑 | 3B + QLoRA | 微调增益 |
| --- | ---: | ---: | ---: | ---: |
| 小类准确率 | 74.0% | 50.5% | **84.9%** | +34.4 pt |

| 正样本 JSON 合规率 | 83.3% | 100% | **100%** | 0 |

> 该口径**不报拦截率**：契约里只允许 8 个大类编码，没有拒答出口。

### 2.3 训练配置与实测（有日志）

| 项 | 值 |
| --- | --- |
| 基座 / 适配器 | Qwen2.5-3B-Instruct（4bit NF4 Double-Quant）+ LoRA |
| LoRA | r=16, alpha=32, dropout=0.05, 7 个 target module |
| 训练 | 3 epochs / **192 步** / lr 2e-4 cosine / warmup 10 / batch 1 × grad_accum 4 |
| 显存优化 | Gradient Checkpointing + `paged_adamw_8bit` |
| 数据 | 256 条（源自项目 231 条案例；32 类，每类 5~9 条；与锚定集字符二元组 Jaccard 最大 0.060） |
| 实测 | **844 秒（14 分钟）** / loss **2.678 → 0.219**（train_loss 0.523）/ 峰值显存 **5.041 GB** / 0 条被截断 |
| 踩的坑 | 契约 1009 字符把上下文顶到 537~851 token，第一版 `max_length=512` 时 **256/256 条全被截断**（模型看不到词表尾部）；改 1024 后 0 条截断 |
