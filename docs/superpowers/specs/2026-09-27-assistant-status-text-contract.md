# 状态文案契约（给前端模型）

日期：2026-09-27
关联后端：`ai-module/core/assistant_graph.py`（`STATUS_TEXT` / `status_text()`）
背景 spec：`docs/superpowers/specs/2026-09-27-orchestration-simplification-design.md`

## 1. 问题（实测）

线上前端产物理有**自己写死的一套**状态文案，与后端真实流程无关：

```
正在检索国家安全标准规范...
正在深度研判...
正在解构现场特征并检索标准库..
正在解析现场图像特征与安全要素.
```

三个毛病：
1. **不跟随流程** —— 后端其实一直在按节点推真实状态（`understand` / `retrieve` / `report`…），前端没用。
2. **营销腔** —— "解构现场特征""深度研判"是自夸，不是状态。用户看状态是想知道"现在到哪一步了"。
3. **标点不统一** —— `..` 与 `.` 混用，明显是不同时期拼的。

## 2. 后端改了什么

- `STATUS_TEXT` 支持**带上下文**：`retrieve` 现在会推
  `正在检索「消防通道占用」的法规与案例...`，而不是固定串。
- 回复节点拆成 4 个（`boundary_reply` / `smalltalk_reply` / `answer_reply` / `fallback_reply`），
  每个都有自己的状态文案。
- 新增两条后端自律，前端可依赖：
  - 每个图节点**必须**有状态文案（有测试锁，缺了会红）
  - 所有文案 ≤ 24 字、非空、不含营销词（有测试锁）

## 3. 前端要做的（只有一件事）

**删掉自己写死的那套状态文案，改为只渲染 SSE `status` 事件的 `content`。**

```
event: {"type": "status", "content": "正在检索「消防通道占用」的法规与案例..."}
```

规则：

| 项 | 要求 |
| --- | --- |
| 数据来源 | 只用 `status.content`，**不要**在前端做 node → 文案的映射（那就又变成两套真相） |
| 展示 | 同一轮内**替换**而不是追加（同一时刻只显示一条状态），`done`/`error` 后清除 |
| 频率 | 只在节点切换时发（后端已保证），不要自己加定时轮播 |
| 文案长度 | 上限 24 字（含标点），设计时按这个宽度留位置 |
| 兜底 | 若 `content` 为空，显示"处理中..."，不要显示空字符串 |

## 4. 验收

1. 前端仓库里搜不到 `解构` / `深度研判` / `智能研判` 这几个词。
2. 一次真实对话里，状态文案按 `understand → retrieve → report` 变化，
   且 `retrieve` 那条带出当前小类名（如「消防通道占用」）。
3. 快速连发两轮，状态不残留上一轮的文案。

## 5. 不做的事

- 不改 SSE 事件名与结构（`status` / `taxonomy` / `chunk` / `interrupt` / `done` / `error` 都不变）。
- 不需要前端做文案本地化或改写。
