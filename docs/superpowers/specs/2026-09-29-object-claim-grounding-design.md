# 规划器漏放修复：物件型小类的「公共空间/物件」原文核对

日期：2026-09-29　　上游：`docs/superpowers/plans/2026-09-29-planner-over-admission.md`
同类上游：`core/scope_policy.py` 里「指示牌 / 光杆标线 有意不收」那段注释（本次要兑现它的结论）

## 1. 要解决的误判（复现证据）

`db/eval_scope_families_e2e_offdomain.txt` 已记录，`db/measure_planner_leak.py` 复现（各 3 次）：

| 输入 | 规划器给的东西 | 现有产物 |
| --- | --- | --- |
| 商场里的指示牌歪了 | `scope=hazard conf=0.90~0.95`，`issues=[traffic/traffic_facility_damage]`，`describe="商场内指示牌歪了"` | **完整报告**，正文引《公路安全保护条例》第 21 条 |
| 楼层指示牌挂得太低了 | `scope=hazard conf=0.75~0.85`，`issues=[traffic/traffic_facility_damage]` 或 `[environment_other/other]` | **完整报告** |

关键事实（决定了修法）：**漏放发生在规划器自己身上** —— 它自己就把 `scope` 判成 hazard、
自己给出 `issues`，不是 `decide_scope` 先看 issues 造成的顺序问题。
（`decide_scope` 里 `issues` 先于 `planner_scope`，但即便把顺序倒过来也拦不住：两条都是 `hazard`。）

## 2. 为什么不在词表里解决

`core/scope_policy.py` 已经论证过：`DOMAIN_KEYWORDS` 是**子串放行**（`any(keyword in text)`），
光杆「指示牌」收录后 4 条域外探针 4/4 被放行 —— 收益（救「路口的指示牌」）小于代价（放进商场/楼层/导览牌）。
这条结论不变，本次**不补词**。

## 3. 为什么不能只要求「原文必须有域锚」

实测（`db/measure_anchor_coverage.py`）：40 条**现实口吻**的本领域表述里，**11 条（27.5%）**
不含任何 `DOMAIN_KEYWORDS` 词 —— 例如「楼上老是往下扔东西」「楼道里闻到很浓的煤气味」
「小区里挖了个大坑，晚上没有灯」。把「必须有域锚」当**通用**必要条件，会把这 27.5% 的真隐患
降级成澄清 —— 比现在的漏放更糟。

**所以规则必须窄**：只对「隐患 = 某个物件坏了」的那几个小类生效，而这类小类的判据里
**物件词或场所词本来就是必要条件**（说「交通设施损坏」而原文没有一个交通设施/道路词，
这句话本身就不成立）。

## 4. 规则

对**物件型小类**（表见下），模型声称的这条隐患必须在原文（用户原话 + 视觉摘要）里
出现下列之一，否则**不采信**：

1. 该类的**物件词**（`OBJECT_CLASS_EVIDENCE`），或
2. **公共空间场所词**（`PUBLIC_SPACE_WORDS`）。

不采信 → `decide_scope` 返回 `ambiguous`（`anchor_domain` → 澄清模板）：
- 不给报告、不进检索、不建单（`scope_guard` 已保证「越界/模糊一律只回答」）；
- 不用 `out_of_scope`：宁可让用户澄清，也不要把真隐患判成「不在我专业范围内」（项目已有的偏向）。

**兜底类（`environment_other/other`）也要依据**：实测里「楼层指示牌挂得太低了」有 3/6 次
被归成 `environment_other/other`（而不是交通设施）—— 同一个漏放的另一个变体。它自己不是一个
物件，没有物件词表，所以规则是：说"其他隐患"时，原文至少要有一个**领域词（`DOMAIN_KEYWORDS`）
或场所词**。这是 §4.2 那张表之外单列的唯一一类。

**为什么这条不是"又一个软约束"**：它是一个纯函数（`decide_scope` 无模型调用），
输入是模型已经给出的 `issues`，输出是可断言的 scope 值 —— 可单测、可端到端测、可做变异实验。
实现名：`unbacked_hazard_claim()`，reason 前缀 `unbacked hazard claim:<小类>`（进 `scope_reason`，可观测）。

### 表（有意只有 5 类，见 §6）

| 小类 | 物件词 | 依据 |
| --- | --- | --- |
| `traffic_facility_damage` | 交通 / 标志 / 信号灯 / 红绿灯 / 护栏 / 隔离墩 / 防撞 / 标线 / 斑马线 | 本次复现的漏放（商场指示牌） |
| `manhole_damage` | 井盖 / 窨井 / 雨水篦 / 雨水口 / 盖板 / 盖子 / 井口 | 同形（隐患=井盖这个物件坏了） |
| `street_light_pole` | 路灯 / 线杆 / 灯杆 / 电线杆 / 灯柱 / 照明 / 杆子 | 同形 |
| `distribution_box_fault` | 配电 / 电箱 / 电表箱 / 变电 / 变压器 / 电闸 | 同形 |
| `facade_fall` | 外立面 / 外墙 / 墙面 / 墙皮 / 瓷砖 / 幕墙 / 招牌 / 广告牌 / 雨棚 / 楼顶 | 同形 |
| `other`（兜底类） | 没有物件词 —— 只要求「领域词或场所词」 | 漏放的第二个变体（3/6 次） |

`PUBLIC_SPACE_WORDS` 有意宽松（路 / 道 / 街 / 巷 / 桥 / 小区 / 院 / 楼道 / 公共 / 户外 /
室外 / 车库 / 停车场 / 广场 / 公园 / 工地 / 天桥 / 隧道 / 涵洞 / 高架 / 地铁 …）：
这些词**只用于放行**（抑制否决），宽松的代价是「少否决」，方向安全，不会造成误拦。

**有意不收进物件词**：`指示牌`（域外家族 商场/楼层/导览牌 —— 与词表同一条理由）、
单字 `灯`（会放过「商场灯箱」这类无关输入）。

## 5. 判据为什么落在 `decide_scope`（而不是 `understand` / 新节点）

- 漏放本身就是**范围判定**错了，范围判定的唯一出口就是 `decide_scope`；
- 它已经是纯函数，扩它不引入模型调用，不破坏「understand 是唯一事实写入者」；
- `scope_guard` 只多传一个 `support_text=vision_summary`（视觉摘要也是原文的一部分）。

## 6. 有意不做的（如实登记）

- **不覆盖**：模型声称某个物件型小类、原文也出现了该物件词，但判断本身错了（如
  「路口的指示牌歪了」被归成交通设施）—— 核对的是「有没有依据」，不是「归得对不对」。
  这里按 `scope_policy` 既有注释的口径：**域锚共现即放行**（这正是那条注释说的做法）。
- **不覆盖**：非物件型小类（占道、堆物、困人…）的漏放。这些类的判据是情形而非物件，
  物件词不构成必要条件，加进去只会误伤。
- **不覆盖**：把这条规则做成"必须有域锚"的通用规则（§3 实测 27.5% 误伤）。
- **有意宽松的一侧**：`PUBLIC_SPACE_WORDS` 里的单字词（路/道/街…）会误配（思路、味道），
  但它的用途只是**放行**，误配的后果是"少否决"（回到现状），不是"误拦"。
- **软的一侧**（同批改动）：规划器提示词补一条判据（商场/办公楼/店内的指示牌、导视牌、
  宣传牌不算交通设施）。它是**判据补充**（与提示词里已有的「消防员招聘条件」那条同形），
  不是保证；保证是本文的代码否决。若它生效，本轮这些输入会直接得到 `out_of_scope`
  而不是 `ambiguous` —— 两种都不给报告。

## 7. 观测与验收

- 单测（`tests/test_scope_policy.py`）：漏放输入必须不再 hazard；5 类的物件词/场所词
  必须逐类放行；非物件型小类不受影响；`support_text`（视觉）能作为依据。
- 端到端（`db/measure_object_claim_grounding.py`，真模型，每例 3 次）：
  9 条越界探针不再产生报告；12 条本领域探针仍判 hazard。
- 变异实验：把否决条件改成恒 False → 漏放必须复现（证明这条测试真的在测东西）。
- 分类评测（`eval_classify.py --samples 3`）：`误拦正样本` 不得增加（本次改动的回归闸门）。

## 8. 实测结果（2026-09-29，部署后）

### 8.1 端到端（`db/measure_object_claim_grounding.py`，线上 106.53.219.214，每例 3 次）

| 组 | 结果 |
| --- | --- |
| 本领域探针 12 条 × 3 次 | **36/36 保持 hazard/emergency**（0 次被核对误伤；非物件型小类、宽松口吻、视觉佐证都不受影响） |
| 越界探针 9 条 × 3 次 | **27/27 次没有进入检索/报告**；其中 27/27 判 `out_of_scope` |
| 两条原始漏放 | 「商场里的指示牌歪了」「楼层指示牌挂得太低了」→ 3/3 次 `out_of_scope`，回复是范围模板，不再是引法规的报告 |

**注意软硬两层的分工**：这 27 次里，`scope_reason` 全部是 `planner out-of-scope` ——
也就是**提示词那条判据先生效了**，代码否决没有被触发。代码否决是**安全网**：
它的存在意义是"提示词哪天不灵了也不会漏放"，而不是"每轮都拦一次"。
（单测与变异实验证明这条安全网本身有效：把否决条件改成恒 False → 漏放复现，见 §7。）

### 8.2 回归闸门（`eval_classify.py --samples 3`，同日同协议 A/B）

| 指标 | 改前（HEAD） | 改后（工作区） | 09-27 记录 |
| --- | --- | --- | --- |
| 小类准确率 总体 | 0.917 ± 0.016 | 0.917 ± 0.016 | 0.938 |
| 大类准确率 总体 | 0.974 ± 0.031 | 0.964 ± 0.016 | 0.958 |
| 负样本拦截率 | 1.000 ± 0.000 | 1.000 ± 0.000 | 1.000 |
| **误拦正样本** | **0 / 192** | **0 / 192** | 0 / 192 |

- 结论 1：**本次改动没有把任何正样本降级**（误拦 0/192，两个臂都是），分类准确率在噪声内不变。
- 结论 2：**0.938 → 0.917 那 0.021 是运行间噪声**，不是本次改动 —— 同一天同协议 A/B 两臂完全一样。
  采样极差（±0.016 ~ ±0.094）就是这个指标的噪声水平。

### 8.3 副作用与残留（如实登记）

- **行为变化（有意）**：「路口的指示牌歪了」从 `out_of_scope` 变成 `hazard` + 报告 —— 这正是
  上面「域锚共现」那条注释说的方向（路口 + 指示牌 = 交通设施）。复测 3/3 次 hazard。
- **未变**：「地上的标线看不清」仍 hazard + 报告（标线是物件词），3/3。
- **不进检索的近邻探针**（防止否决过度开火，3/3 全部 hazard）：
  「商场门口的井盖没了」「医院门口的路灯不亮了」「写字楼门口的护栏被撞倒了」。
- **观察到的既有小毛病（本次未修，属观感层）**：越界输入若被规划器标了 `premises_scope=indoor`，
  回复会在范围模板前多挂一句户内提示（「商场里的指示牌歪了」出现过这个前缀）。
  它不改结论，只在越界回复里多一句话；已登记。
