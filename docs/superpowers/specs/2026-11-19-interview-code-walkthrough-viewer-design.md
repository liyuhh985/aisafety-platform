# 面试代码讲解册设计

> 状态：已确认方向，待用户审阅
> 日期：2026-11-19
> 范围：异步建单链路的可维护、离线代码学习入口

## 1. 目标

解决三个问题：

1. 核心代码散落在 Java、Python、Vue 多个文件中，按业务链路阅读成本高。
2. 对话中直接贴源码容易截断，也无法稳定对应真实行号。
3. 平时复习、共享屏幕和模拟面试需要不同的展示方式。

最终交付一个离线 HTML 单页，源码片段由工具从真实文件提取，中文讲解作为独立元数据维护。

## 2. 非目标

- 不替代 IDE 编辑和调试。
- 不复制整个代码库。
- 不做在线代码浏览器、账号系统或后端服务。
- 不在第一版覆盖全部业务模块。
- 不直接修改被讲解的业务源码。

## 3. 第一版范围

第一版只覆盖“异步建单”主链路，规划 9 个章节：

1. Java SSE 入口
2. LangGraph 确认与提交节点
3. Python request + outbox 事务
4. Relay 扫描与 RabbitMQ 投递
5. Java RabbitMQ Listener
6. Java `createAi()` 事务与幂等
7. 成功回执与 Python 状态更新
8. `RequestReconciler` 超时对账
9. 前端确认、SSE 与分级轮询

预计 20～30 个精确代码片段。后续章节复用同一数据结构扩展。

## 4. 文件结构

- 生成器：`tools/build_interview_code_walkthrough.py`
- 讲解元数据：`tools/interview_code_walkthrough/manifest.json`
- 生成结果：`output/interview-code-walkthrough/index.html`
- 生成说明：`output/interview-code-walkthrough/README.md`

生成器只读取项目源码；为讲解而做的中文说明存放在 manifest，不污染业务文件。

## 5. 数据结构

每个章节包含：

- `id`：稳定标识
- `title`：章节名称
- `summary`：这一章解决什么问题
- `snippets`：按阅读顺序排列的代码片段

每个代码片段包含：

- `file`：项目相对路径
- `method`：类名或函数名
- `start` / `end`：一基行号
- `startAnchor`：用于校验起始行的非空文本；校验时去除首尾空白后，必须与 `start` 行源码完全相等
- `title`：片段标题
- `explain`：大白话说明
- `interviewQuestions`：面试官可能的追问
- `interviewAnswers`：与追问一一对应的参考答案
- `lineNotes`：按片段内行偏移定位的语法注或方法注，并用 `kind=syntax|method` 区分
- `pitfalls`：不能说错或不能过度声称的边界

## 6. 构建流程

1. 读取并校验 manifest。
2. 按相对路径读取真实源码。
3. 校验文件存在、行号范围合法、起始锚点匹配。
4. 从源码中原样提取片段，不手工重写代码。
5. 计算片段哈希并写入生成时间、源文件路径和行号。
6. 将源码、说明、追问和边界一起写入离线 HTML。
7. 任一片段校验失败时停止构建并输出明确错误，不生成带错误内容的页面。

## 7. 页面体验

### 左侧导航

- 按业务链路排列 9 个章节
- 支持章节搜索和片段搜索
- 显示“已掌握”进度

### 右侧内容

每个片段固定展示：

- 文件路径、类名或方法名、行号范围
- 带真实行号的源码
- 紧跟相关源码行的语法注或方法注
- 每段 10～20 行以内的中文解释
- “面试官可能问”，每个问题用可展开元素隐藏参考答案
- “容易讲错的边界”
- 复制路径按钮
- `vscode://file/...:line` 跳转链接，失败时可复制路径手动打开

### 两种模式

- 学习模式：源码、解释、追问、边界全部显示
- 面试模式：隐藏解释，只保留业务节点和源码，用于共享屏幕演练

“已掌握”状态保存在浏览器 `localStorage`，不依赖服务端。

## 8. 源码变更与过期防护

- 每个片段必须提供 `startAnchor`。
- 若源码修改导致起始行不再是预期内容，构建失败并提示重新校准行号。
- 页面显示生成时间和源文件路径。
- 页面不缓存外部 CDN；CSS 和 JavaScript 内联，保证离线可用。
- 不把源码复制到长期手工文档中，避免两份真相源。

## 9. 错误处理

- manifest 缺失或 JSON 非法：终止并打印修复位置。
- 源码文件不存在：终止并列出缺失路径。
- 行号越界：终止并显示合法范围。
- 起始锚点不匹配：终止并显示期望文本、实际文本和建议操作。
- HTML 生成失败：不覆盖上一次成功产物，先写临时文件再原子替换。

## 10. 验证方案

- 为路径解析、行号提取、锚点校验和缺失文件增加单元测试。
- 使用当前项目生成一次完整页面，检查 9 个章节均存在。
- 验证每段行号与 IDE 打开后的真实行号一致。
- 用浏览器检查目录跳转、搜索、模式切换和进度保存。
- 修改一个被引用文件后故意制造锚点不匹配，确认构建会失败并给出清晰错误。

## 11. 验收标准

满足以下条件即视为第一版完成：

1. 只用一个本地 HTML 文件即可完整浏览异步建单链路。
2. 页面中的每个代码片段都来自真实源码，并带准确行号。
3. Python 片段按小段展示，每段附带语法和业务解释。
4. 支持学习模式和面试模式。
5. 源码位置变化时构建不会静默展示错误代码。
6. 生成器可在一条命令下重复运行。
7. 不改动现有 Java、Python、Vue 业务源码。

## 12. 实施顺序

1. 定义 manifest 和章节初稿。
2. 实现源码提取、锚点校验和 HTML 生成。
3. 增加单元测试。
4. 生成第一版并检查浏览器效果。
5. 根据实际阅读体验调整章节和片段粒度。
