# Agent 应用开发求职学习计划设计

## 目标

围绕 Agent 应用开发、LLM 应用开发和 AI 应用后端实习岗位，重整后续学习计划。计划服务于 2028 年毕业、下学期进入大三上的求职准备，重点提升两个现有项目的可面试深度，而不是增加第三个大型项目或重复讲解整体链路。

## 目标岗位画像

主目标是初级 Agent 应用开发、LLM 应用开发和 AI 应用后端岗位。学习主线覆盖：

- Python/FastAPI 或 Java/Spring Boot 后端开发；
- Prompt、结构化输出、Tool Calling、Workflow 和 Agent 编排；
- RAG、Embedding、向量检索、Memory 和效果评估；
- SSE、异步任务、超时、取消、重试、限流和资源释放；
- MySQL、Redis、认证授权、接口设计、日志、测试和 Docker 部署。

微调作为后期加分专题，安排一次可复现的 LoRA/QLoRA 最小实验。全量训练、模型研究和 GPU 分布式训练不属于当前主线，除非招聘核查显示目标岗位明确要求。

## 核心原则

### 1. 以招聘需求校准内容

每个阶段开始前核查近期公开招聘信息，至少记录岗位名称、发布时间或访问日期、硬性要求、高频技术、加分项和学历/实习要求。单个岗位不能决定学习方向；只有在多个目标岗位中重复出现且与项目相关的能力，才进入主计划。

### 2. 以项目深度代替项目数量

- AI 安全隐患平台是 Agent 主项目，重点展示编排、Vision、Retrieval、Report、SSE、取消和可靠性。
- yydp 是 Java 后端能力项目，重点展示认证授权、事务、Redis、缓存一致性、接口设计和并发。
- 不新增第三个完整业务项目。若后续出现明确能力缺口，只增加一个可在数天内完成的专项实验，并接入现有项目或单独作为技术验证。

### 3. 每次只深挖一个具体主题

整体链路只作为定位背景，不再作为每天的主要教学内容。每个主专题必须落到真实代码、请求流、边界情况、测试或指标以及面试表达。

### 4. 算法采用 LeetCode 题目驱动

每天保留 30 到 45 分钟。学习顺序为：独立读题和实现、必要提示、复杂度分析、边界复盘、变体追问。算法不再单独重复抽象模板讲解。

## 单专题验收标准

每个 Java 或 Agent 专题完成以下结果：

1. 一句话定义、适用场景和不适用场景；
2. 当前项目中的文件位置和真实调用链；
3. 核心代码或最小可运行示例；
4. 至少一个异常、并发、超时或数据隔离边界；
5. 一个测试、压测、日志证据或效果对比；
6. 面试主回答和三到五轮追问答案；
7. 一条可以放入简历但不夸大的项目表述。

## 阶段结构

### 阶段一：求职基线和项目盘点

核查目标岗位，整理能力矩阵；分别画出两个项目的模块边界；选择一个可以完整追踪的真实功能作为主线。输出项目运行说明、代码索引、当前差距表和第一版简历项目表述。

### 阶段二：Agent 核心能力深挖

按独立专题学习 Orchestrator、结构化输出、Tool Calling、RAG 检索、Memory/Session 和评估。每个专题都必须结合安全平台代码，并补充失败结果、降级策略或评估样例。

### 阶段三：运行时与后端工程化深挖

专门处理 SSE 生命周期、Java 线程池、Python 事件循环、跨服务取消、超时、重试、幂等、认证授权、Redis 和数据一致性。安全平台与 yydp 分别承担 Agent 运行时和 Java 业务工程案例。

### 阶段四：交付能力和专项加分

补齐 Docker、配置管理、日志和 Trace、成本与延迟记录、评估集、部署说明。根据招聘核查结果安排一次最小 LoRA/QLoRA 实验或其他高频专项，不做与目标岗位无关的扩展。

### 阶段五：面试和投递闭环

形成 3 分钟项目介绍、10 分钟架构讲解、模块级代码追问、故障定位题和 Agent 设计题。每周至少一次模拟面试；在达到第一个项目验收门槛后开始低频投递，用真实反馈修订计划，而不是等到全部学完再投递。

## 每日时间结构

默认 4 小时：

- LeetCode：30 到 45 分钟；
- 当日主专题精讲与代码阅读：90 分钟；
- 项目改动、测试或另一个方向的关联练习：75 分钟；
- 面试表达、招聘需求记录和复盘：30 到 45 分钟。

每天只设一个主专题。Java 和 Agent 不要求每天都进行同等深度的概念讲解；另一个方向只保留与主专题直接相关的练习或复习。

## 成功标准

计划完成时，应能在不依赖笔记的情况下：

- 独立讲清安全平台一个完整 Agent 功能和关键代码；
- 独立讲清 yydp 一个后端核心功能及其数据和并发边界；
- 写出常见 LeetCode 模式题并解释复杂度；
- 针对 RAG、Tool Calling、Memory、SSE 和后端可靠性回答连续追问；
- 运行项目、展示测试或指标，并诚实说明尚未解决的问题；
- 根据招聘信息调整简历和学习优先级。

## 风险控制

- 防止“学了很多名词但没有代码证据”：每个专题必须绑定文件、测试或运行结果。
- 防止重复架构复述：整体链路每周最多复盘一次，其他时间只讨论当前模块。
- 防止盲目追逐微调和新框架：先看目标岗位频率和项目收益，再安排专项。
- 防止学历和无实习经历带来的筛选压力：提前准备可运行项目、清晰简历和模拟面试，并用投递反馈校准计划。
