# 阶段 4 设计：`missing` 喂报告 + B 类缺失写成条件分支

日期：2026-09-28　　上游：`docs/superpowers/plans/2026-09-27-dialogue-quality-execution.md` 的「阶段 4」

## 1. 要解决的误判

报告对「缺失信息」原来只有两种处理，都不合格：

| 处理 | 后果 |
| --- | --- |
| **省略** | 报告给错法条 —— 缺的那项明明会改变法规适用 |
| **写空话**（「关于持续时长，信息尚不完整，建议进一步核实。」） | 把不确定性丢回给用户，**等于没做判断** |

用户给的反例是「占道是长期还是临时」：**不影响下一步动作**，但**影响法规适用与处罚档次**。
所以正确写法是**条件分支**：

> 持续时长未知：若为长期占用，适用《城市道路管理条例》第 X 条（可处罚）；
> 若为临时占用，适用第 Y 条（责令改正）。

## 2. 三类缺失的分工（上游：阶段 2 的 A/B/C 划分）

| 类 | 判据 | 追问 | 报告材料 | 报告写法 |
| --- | --- | --- | --- | --- |
| **A 决策级** | 缺了它，风险等级或该采取的动作会判错 | 是 | `[仍缺信息]` + 槽位问句 | 追问那一个 |
| **B 报告级** | 结论与动作不变，但法规适用 / 责任归属 / 处罚档次不同 | 否 | `[法规适用待确认]` + 槽位问句 | **分情况判断「若…则…」** |
| **C 装饰级** | 结论、动作、法规都不变 | 否 | **不进材料** | 不提 |

字段来源：`issue["missing"]`（A）与 `issue["report_missing"]`（A+B），由阶段 2 的
`rebuild_missing` / `rebuild_report_missing` 在 `understand` 里算好；本阶段**只消费**。

## 3. 材料形状（`_issue_blocks`）

只缺 `impact`(B) 的消防通道，材料是：

```
[隐患1] 消防通道占用（信息完整）
[视觉分析]
[检索法规] ...
[检索案例] ...
[法规适用待确认] 是否影响消防车或人员通行？（缺它不影响结论和处置方向，但会改变适用的法规条款、责任归属或处罚档次）
```

关键点：**B 类取的是 `report_missing` 减掉 `missing`**（`b_only`）——
A 类已经走 `[仍缺信息]` 那一行，不能在 B 行里重复。

「信息完整」这个标注**没有改**：它指的是决策级完整（够不够出三段式完整报告），
和「有一项 B 类待定」并不矛盾 —— 所以 `report_full` / `preliminary` 的边界不受影响。

## 4. 提示词形状（`_report_rules(..., branch=...)`）

只有材料里**真的出现** `[法规适用待确认]` 时才注入这段（`report_branch_keys(state)` 非空）：

> 材料里标了「[法规适用待确认]」的，是缺了也不影响结论和处置方向、但会改变适用的法规条款、
> 责任归属或处罚档次的那一项。这种信息不要省略，也不要写「信息尚不完整」「建议进一步核实」
> 这类把核实退回给用户的空话；要用「若…则…」的分情况判断，把每一种可能各自的适用依据都写出来。

为什么**要门控**：这段说明本身会提到 B 类待定，如果无条件注入，模型会以为还有信息没确认；
而且「[法规适用待确认]」这个标签会出现在无关提示词里，让「只有 B 类写分支」变得不可测。

**没有回退小标题模板**：这段是**内容要求**，和阶段 3 的 (b)（初步报告用自然段落、
至多一个问句）是两条独立的约束，互不覆盖。

## 5. 空话检测（`empty_talk_hits`，弱层次，只告警）

标记表只收**把核实退回给用户**的措辞：

```
建议进一步核实 / 建议进一步确认 / 建议进一步了解 / 建议进一步查明
建议自行核实 / 建议自行确认 / 建议核实
有待进一步核实 / 有待核实 / 需进一步核实 / 尚待核实 / 待进一步核实
```

**为什么不收「信息不完整」这类断言本身**：线上第 1 轮实测的**合格**文本里就有
「目前信息还不完整，需要确认的问题是：被什么东西占用了」—— 它说了「不完整」，
但紧跟一个具体到槽位的确认项。按断言去抓会误伤它。这条区分有测试钉住。

**兜不住的**（如实写下来）：

- 只做词面命中，不判语义。「信息不完整」+ 空话混写、或换一种说法往回推，都可能漏检。
- 所以这一层和 `preliminary_coverage` 一样：**只告警、不改写正文**。
- 触发条件由测试用 `caplog` 断言；`report_full` 与 `preliminary` 两档都接上了。

### 一个由本阶段引入的副作用（要留意）

规则里让模型说出「法规适用待确认」这个词之后，模型确实会照做（实测原文里出现过
「（法规适用待确认）」）。而 `_PRELIM_MISSING_MARKERS` 里含「待确认」——
所以**模型原样复述材料标签，就会顺带让 coverage 的 `missing` 判为 True**。
这会让那个信号**变弱**（更容易误报「已覆盖」），而不是变强。

影响面：`preliminary_coverage` 只用来**打日志**（不决定追问、不改写正文 ——
决定补不补追问的是 `preliminary_question_tail`，它看的是问号）。所以这是可观测性问题，
不是功能问题。**没有为此改动它**，只登记。

顺带：实测发现 coverage 对真实措辞漏检（模型写「目前仍然缺的就是占用时长」「这一项尚未确认」），
已补 `仍然缺` / `尚未确认` / `还没确认` 三个标记（有测试）。

## 8. 方法学局限（不粉饰）

1. **每例只跑一次，无方差数据。** 三个用例 × 单次采样，文案类结论**只对这三组输入成立**。
2. **交付侧的测试用的是 stub 回复**（`test_branch_wording_is_delivered_and_not_flagged`
   等），它们证明的是「条件分支能穿过执行器、不会被削掉」，**不是**「模型一定会那样写」。
   后者的证据只有第 6 节那次实测。
3. 案例 B 的检索结果是「库内暂未检索到」（语料里没有井盖类案例），所以那条的
   「类似案例」段为空 —— 与本次改动无关。
