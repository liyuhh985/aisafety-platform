# 真实图测评集 · 标注规则

> 定稿日期：2026-10-30
> 本文件是唯一判定口径。所有审核必须照此执行，不得逐批自创标准。

---

## 一、样本准入（必须全部满足）

| # | 条件 | 说明 |
|---|---|---|
| 1 | **真实拍摄照片** | 不是 AI 生成图、不是插画/漫画/示意图/CAD 图、不是商品广告图 |
| 2 | **无图库水印** | 排除 dreamstime / shutterstock / 视觉中国等带售卖水印的图 |
| 3 | **最短边 ≥ 800px** | 低于此值直接弃用，不进入人工复审 |
| 4 | **画面主体明确** | 一眼能看出拍的是什么，不是纯背景、纯局部特写 |

## 二、隐患现场 vs 整改过程（关键规则）

**只收「隐患现场」图。** 判定依据是**画面主体呈现的状态**，不是新闻标题写了什么。

| 收 | 不收 |
|---|---|
| 井盖破损、缺失、塌陷，洞口裸露 | 工人正在更换井盖、铺设沥青 |
| 消防通道被车辆占满 | 交警正在贴条、拖车 |
| 垃圾成堆、无人清理 | 环卫工正在清扫、清运车作业 |
| 墙面开裂、外墙脱落 | 搭脚手架正在维修 |
| 围挡缺失、开挖面裸露 | 工人正在安装围挡 |

**理由**：整改图的风险状态已经消失或被处置，作为"隐患识别"的题目会污染标签。

**边界情况处理**：
- 画面里既有隐患又有工人 → 看**隐患是否仍是主体**。若隐患占据画面主体、工人只在边缘，算隐患现场。
- 「已修复」的对比图（左破损 / 右修好）→ **不收**，属拼接图。

## 三、文字处理（核心规则：文字是"场景的一部分"还是"唯一信息源"）

**判据只有一条：把文字全部遮住之后，还能看出这是该类隐患吗？**

- **还能看出来** → 收。文字只是现场的附属物。
- **看不出来了** → 不收。文字就是全部信息，属于"文字题"而非"识图题"。

### ✅ 收（文字是真实场景的一部分）

| 例子 | 为什么收 |
|---|---|
| 车辆停在黄网格上，地面喷着「消防通道」 | 遮住字仍能看出"车堵住了一条通道" |
| 车停在「禁止停车」标牌旁 | 遮住字仍能看出"车停在不该停的位置" |
| 垃圾桶上印着「可回收物」，桶边堆满垃圾外溢 | 遮住字仍能看出"垃圾堆积外溢" |
| 井盖破洞，井圈铸着「污水」二字 | 遮住字仍能看出"井盖破损" |
| 破损盲道上停着电动车 | 遮住字仍能看出"占用通道" |

**要求**：这类图必须标 `text_in_image: true`，并把文字内容记进 `text_content`。
评测时单独统计这组的准确率，与"无文字组"对比，用于判断模型是否在读书而非读图。

### ❌ 不收（文字是唯一信息源）

| 例子 | 为什么收不了 |
|---|---|
| 新闻截图，画面上盖着大字「违规停车」 | 遮住字就只剩一张普通街景，看不出问题 |
| 手持打印纸/文件特写，纸上写着隐患名称 | 整张图就是一个文字告示 |
| 纯文字宣传图、标语图、海报 | 没有隐患现场 |
| 卡通插画配文字说明 | 非真实照片，且信息靠文字 |
| 「曝光台」类合成图：一张图 + 大字标题 | 信息主体是标题 |

**特征**：这类图的文字**占据画面主体或压在画面上**（叠加字、字幕条、大标题），而不是"物体上本来就有的字"。

### ⚪ 无关文字（不影响判定）

车牌、店招、品牌名、媒体台标、水印、广告牌内容 —— 记入 `text_content`，但不影响收或不收。

### 操作口诀

> **物体自带的字 → 可收；后来压上去的字 → 不收。**

## 四、类别归属

- 类别码取自 `_taxonomy.json`，路径格式 `大类/小类`。
- 一张图可能有多个隐患 → 主类别填最突出的，`secondary_categories` 填其余。
- **类别重叠时按"视觉主体"判定，不按"潜在后果"判定**。
  - 例：井里塞满垃圾 → 视觉主体是垃圾 → `garbage_pile`，而非 `manhole_damage`。
  - 例：开挖土石堆在路边无围挡 → 视觉主体是土石堆 → 若判 `garbage_pile` 更贴合，就不要硬塞 `no_barrier`。
- **判不了就淘汰，不要硬凑。** 每类宁可 10 张干净样本，不要 30 张含糊样本。

## 五、难度分级

| 等级 | 含义 | 举例 |
|---|---|---|
| `easy` | 主体占画面 1/3 以上，特征清晰，光线正常 | 正面近拍破损井盖 |
| `medium` | 主体占画面 1/10~1/3，或需结合上下文判断 | 中景拍整条路的井盖 |
| `hard` | 主体小、逆光、遮挡、模糊、多隐患混杂 | 远景、夜间、雨雪天 |

**要求**：每类尽量凑齐 easy/medium/hard 各若干，全 easy 的类别没有区分度。

## 六、负样本（正常场景）

用于测试误报率。负样本必须是**同类场景下的正常状态**：

| 类别 | 负样本应拍什么 |
|---|---|
| 井盖破损 | 完好平整的井盖 |
| 消防通道 | 黄网格空置、无车 |
| 垃圾堆积 | 整洁街道、垃圾桶规范摆放 |
| 车辆占道 | 车辆规范停在车位线内 |
| 未设围挡 | 围挡完整规范的工地 |

**负样本不得有隐患**。若发现所选图其实有隐患（如"完好井盖"实为塌陷），必须剔除——这类误判已经发生过一次，需警惕。

## 七、审核产出格式

```json
{
  "file": "MAN0001.jpg",
  "verdict": "keep",
  "has_hazard": true,
  "major_category": "municipal",
  "subcategory": "manhole_damage",
  "severity": "高",
  "key_evidence": "30字内描述画面可见特征",
  "multi_hazard": false,
  "secondary_categories": [],
  "text_in_image": false,
  "text_content": "",
  "difficulty": "easy",
  "label_confidence": "high",
  "is_negative_sample": false,
  "reject_reason": ""
}
```

`verdict` 取值：`keep`（收）/ `reject`（不收，须填 `reject_reason`）

`reject_reason` 常用值：
- `整改中` — 工人正在作业，隐患已进入处置
- `正面案例` — 设施完好规范
- `文字泄题` — **仅限文字是唯一信息源**（叠加字幕/大标题/手持告示/纯标语图）；物体自带的字不算
- `图库水印` — 带售卖水印
- `非该类别` — 拍的是别的东西
- `信息不足` — 看不清、无法判断
- `示意图/广告` — 非真实照片
- `拼接/对比图` — 多图拼合

## 八、按此规则处理消防通道类

消防通道的典型特征就是「黄网格 + 地面文字」。按新规则：

- 车辆停在黄网格上，地面有「消防通道」字样 → **收**（遮住字仍能看出车堵住通道）
- 空旷黄网格配大字标语 → **不收**（遮住字啥也没有）
- 交警执法截图叠加标题大字 → **不收**（信息主体是标题）

即：该类会保留相当一部分样本，但必须在 `text_content` 里如实记录文字内容，评测时分组统计。
